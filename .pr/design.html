A failed startup task is not an existing planner

Explicit Plan retry can replace an accepted Cloud startup task that reached ERROR without creating a child. Working tasks, ready planners and existing children retain duplicate-creation protection. Source commit 0626db873fb81fbd71c1802a66f619bcfc2259c3.

3. Regression proof and remaining live verification

Before: a supported terminal ERROR leaves hasPlanner true and only one create request after explicit retry. Clearing saved state permits a second request. After: 65 focused tests pass across five suites; tests use real hooks, resolver, polling, stores and persistence with API service boundaries replaced.

Integration cases cover two simultaneous consumers, pending remount, initial-message forwarding, ERROR retry, rejected retry and preserved WORKING/READY/created-child ownership. Polling tests cover distinct backend/org/parent identities.

No endpoint, SDK behavior, minimum server version, public payload or translation changes. Local planner behavior stays on its existing route. The full project suite was not run.
